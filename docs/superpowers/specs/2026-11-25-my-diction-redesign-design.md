# My Diction 화면 개편과 메모 기능 설계

작성일: 2026-11-25 · 상태: 사용자 승인 대기
바탕 문서: `docs/specs/2026-11-23-announcer-app-design.md` (v1 설계). 이 문서는 v1 설계를 바꾸는 부분만 적는다. 여기 없는 내용은 v1 설계를 따른다.

## 1. 무엇을, 왜

사용자가 준 디자인 시안 두 장(녹음 화면, 메모 창)에 맞춰 앱을 다시 그리고, 시안에 있는 새 기능을 넣는다. 지금 앱(v0.1.0-dev)은 기능은 갖췄지만 화면이 기본 머티리얼 모양이고, 읽는 동안 원고의 어디를 읽는지 보여주지 못한다. 시안은 방송 원고 프롬프터처럼 지금 읽는 줄을 따라가고, 끊어 읽기 표시와 자주 틀리는 곳, 사용자의 메모를 원고 위에 함께 보여준다.

앱 이름은 **My Diction**으로 바꾼다 (사용자 결정). 녹음 화면 맨 위의 "온에어."는 앱 이름이 아니라 녹음 화면의 제목으로 쓴다 (설계자 판단).

## 2. 정해진 것 (사용자 결정)

1. **읽는 위치는 실시간 인식으로 따라간다.** 녹음하는 동안 폰 안의 음성 인식으로 들린 말을 원고와 계속 맞춰 보고, 지금 읽는 줄과 "대본 %"를 움직인다.
2. **끊어 읽기 표시는 자동으로 넣고 사용자가 고칠 수 있다.** 쉼표 뒤에 `/`(쉼), 마침표·물음표·느낌표 뒤에 `//`(숨)을 자동으로 넣는다. 어절 사이를 누르면 표시 없음 → `/` → `//` → 표시 없음 순으로 바뀐다. 강조는 메모에서 "강조"를 고르면 그 어절에 파란 밑줄로 표시된다.
3. **앱 이름은 My Diction.**

## 3. 화면

### 3.1 전체 구성

아래에 탭 세 개를 둔다: **대본 / 녹음 / 기록**.

- **대본:** 원고 목록과 붙여넣기 (지금의 원고 목록·붙여넣기 화면을 새 스타일로). 원고를 누르면 그 원고가 "지금 원고"가 되고 녹음 탭으로 넘어간다.
- **녹음:** 시안 1·2의 화면. 지금 원고가 없으면 "대본 탭에서 원고를 골라 주세요"와 대본 탭으로 가는 버튼을 보여준다.
- **기록:** 지금 원고의 연습 기록 (지금의 기록 화면을 새 스타일로). 기록을 누르면 결과 화면이 열린다.

### 3.2 녹음 화면 (시안 1·2)

```
 온에어.                        [ON AIR]   ← 녹음 중에만 빨갛게 빛남
 9시 뉴스 오프닝                            ← 원고 제목
 / 쉼  // 숨  ▬ 강조  〰 자주 틀림          ← 표시 설명

   안녕하십니까. //                         ← 지나간 줄: 작고 흐림
   11월 23일, /
 ▶ 9시 뉴스를                                ← 지금 줄: 크고 진함
 • 시작하겠습니다. //  ③                     ← 자주 틀림: 빨간 물결 밑줄 + 횟수
   [받침 'ㅆ' 또렷하게]                       ← 메모: 어절 아래 분홍 말풍선
   먼저 / 오늘의                             ← 다음 줄: 흐림

 속도 (느림 [적당] 빠름)   크기 (작게 [적당] 크게)
 ▮▮▯▮▮▮▮▯▮▮▮|▮|▮▯▯▮▮▮▯▯                    ← 소리 파형
 대본 62%                          남은 0:28
 ━━━━━━━━━━━━━━●━━━━━━━──────                ← 진행 막대 (빨간 점 = 자주 틀리는 곳)
     (릴)        [■ 녹음/정지]        (릴)    ← 녹음 중 릴이 돈다
```

- **줄 나누기:** 원고를 끊어 읽기 표시(`/`, `//`)에서 줄을 나눈다. 표시가 없는 긴 구간은 화면 폭에 맞춰 자연스럽게 줄바꿈한다.
- **지금 줄:** 녹음 전에는 첫 줄, 녹음 중에는 실시간 인식이 찾은 위치의 줄. 지금 줄이 화면 가운데쯤 오도록 부드럽게 스크롤한다.
- **속도:** 최근 10초 동안 원고에서 나아간 음절 수로 1분당 음절을 구해 느림(280 미만) / 적당 / 빠름(380 초과)으로 표시한다. 초기값이며 상수로 둔다.
- **크기:** 최근 0.5초 소리 크기로 작게(-30dBFS 미만) / 적당 / 크게(-10dBFS 초과)로 표시한다. 초기값이며 상수로 둔다.
- **파형:** 0.1초마다 소리 크기 막대 하나. "크게" 범위의 막대는 빨간색.
- **대본 %:** 원고 전체 음절 중 지금 위치까지의 음절 비율.
- **남은 시간:** 남은 음절 ÷ 지금 속도. 속도를 아직 모르면(처음 5초) 1분당 350음절로 계산한다.
- **녹음 버튼:** 가운데 검은 원 (녹음 전 빨간 원 아이콘, 녹음 중 빨간 네모). 녹음이 끝나면 결과 화면으로 넘어간다.
- **ON AIR:** 녹음 중에는 빨간 글씨와 빛, 녹음 전에는 회색 테두리.

### 3.3 원고 위 표시와 편집

- **어절 사이를 누르면** 그 자리의 끊어 읽기 표시가 바뀐다 (없음 → `/` → `//` → 없음). 녹음 중에는 편집하지 않는다.
- **어절을 길게 누르면** 메모 창(시안 2 아래쪽)이 열린다.
- **자주 틀림:** 이 원고로 인식까지 끝난 녹음 중, 그 어절이 "다르게 들림" 또는 "빠뜨림"이었던 횟수가 2번 이상이면 빨간 물결 밑줄과 동그라미 안 횟수를 붙이고 줄 왼쪽에 빨간 점을 찍는다.
- **강조:** "강조" 메모가 있는 어절은 파란 형광펜 밑줄.
- **메모:** 메모가 있는 어절 아래에 분홍 말풍선으로 메모 글을 보여준다.

### 3.4 메모 창 (시안 2 아래)

```
 ─────
 길게 눌러 메모
 시작하겠습니다                              ← 누른 어절
 (발음) (속도) (억양) (강조)                 ← 하나 고름
 받침 'ㅆ' 또렷하게 |                        ← 메모 글
 녹음 3번 중 3번 틀림              [저장]
```

- 어절 하나에 메모 하나. 이미 있으면 불러와 고치고, 글을 비우고 저장하면 메모를 지운다.
- 종류는 발음 / 속도 / 억양 / 강조 중 하나 (기본값: 발음).
- "녹음 N번 중 M번 틀림"의 N은 인식까지 끝난 녹음 수, M은 그중 이 어절이 다르게 들렸거나 빠진 횟수. 녹음이 없으면 이 줄을 숨긴다.

### 3.5 결과 화면

v1의 결과 내용(걸린 시간, 1분당 음절, 억양 선, 다르게 들린 단어, 다시 듣기)을 그대로 두고 새 스타일로 다시 그린다. 시안에 결과 화면이 없으므로 녹음 화면과 같은 색·글꼴을 쓴다 (설계자 판단).

### 3.6 스타일

- 바탕: 따뜻한 미색(#F5F3EE 근처), 글자: 거의 검정, 흐린 글자: 회색.
- 빨강(쉼·숨 표시, ON AIR, 자주 틀림, 녹음 정지 아이콘), 파랑(강조, 진행 막대), 분홍(메모 말풍선, 선택된 메모 종류).
- 한글 글꼴은 가는 획의 고딕(Pretendard 또는 Noto Sans KR 계열)을 앱에 넣어 쓴다. 인터넷에서 글꼴을 받지 않는다 (v1 개인정보 제약).
- 이번 개편은 밝은 화면만 만든다. 폰이 어두운 모드여도 같은 밝은 화면을 쓴다 (설계자 판단).

## 4. 실시간 인식 (사용자 결정 A)

- `whisper_ggml`의 실시간 세션(`transcribeLive` 계열)을 쓴다. 녹음 PCM16 바이트를 그대로 넣고, 세션이 내놓는 "지금까지 들린 전체 글"이 바뀔 때마다 원고와 맞춰 본다. 인식은 별도 워커에서 돌아 화면을 막지 않는다.
- **원고 위치 찾기:** 들린 글을 읽는 소리(`readAloud`)로 바꾸고, 원고 앞부분과 글자 단위로 맞춰(원고 끝은 자유롭게 남기는 정렬) 들린 글의 끝이 원고의 몇 번째 음절에 해당하는지 구한다. 위치는 뒤로 가지 않는다. 한 번에 원고 한 줄을 넘는 큰 점프는 두 번 연속으로 같은 결과가 나올 때만 받아들인다.
- **느린 폰 대비:** 목소리가 계속 들어오는데 6초 넘게 들린 글이 늘지 않으면 "실시간 인식이 늦다"로 보고, 그 녹음이 끝날 때까지 위치를 목소리 시간으로 추정한다 (목소리가 난 시간 × 지금 속도, 속도를 모르면 1분당 350음절). 화면에는 작게 "위치를 추정하는 중"이라고 알린다.
- **녹음이 끝난 뒤:** 실시간 인식이 끝까지 정상이었으면 세션의 최종 글로 원고 비교를 하고, 녹음 파일 전체를 다시 인식하지 않는다. 늦어졌거나 오류가 났으면 지금처럼 녹음 파일 전체를 30초 조각으로 인식한다.
- 녹음 버튼을 누를 때 실시간 세션을 시작한다. 모델을 처음 올리는 몇 초 동안은 녹음은 바로 시작하고 위치만 추정으로 시작한다.
- 실시간 세션은 한 번에 하나만 돌 수 있다. 녹음이 끝나면 세션을 반드시 닫는다.

## 5. 저장 (DB 스키마 v3, 추가만)

- `scripts`에 `pause_json` 열 추가: 어절 사이 표시. 어절 i 뒤의 표시를 `{i: "pause"|"breath"}`로 저장한다. 값이 없으면(NULL) 아직 자동 표시를 만들지 않은 원고로 보고, 처음 열 때 자동 표시를 만들어 저장한다.
- `memos` 테이블 추가: `id, script_id, word_index, kind(pronunciation|speed|intonation|emphasis), text, created_at`. `(script_id, word_index)`는 하나만.
- 어절 번호는 원고 본문을 공백으로 나눈 순서다. 원고 본문은 고칠 수 없으므로(v1과 같음) 번호가 바뀌지 않는다.
- 원고를 지우면 메모도 함께 지운다.
- 업그레이드는 v1 원칙대로 열과 테이블을 추가만 하고, v2 데이터가 그대로 남는지 테스트한다.
- "자주 틀림"은 따로 저장하지 않고, 저장된 연습 기록의 비교 결과(`marks`)에서 계산한다. 덧붙임(extra)을 뺀 비교 결과는 원고 어절과 순서대로 하나씩 맞는다.

## 6. 목표·비목표·실패

**목표:** 시안대로의 세 탭 화면, 실시간 위치 따라가기, 끊어 읽기 표시 자동 생성과 편집, 어절 메모, 자주 틀림 표시, 앱 이름 변경.

**하지 않는 것:** 원고 본문 고치기, 여러 어절에 걸친 메모, 메모 검색·모아보기, 어두운 모드 디자인, 클라우드 동기화, B 기능(유료 발음 평가), iOS 화면 확인(Windows라 빌드 불가).

**실패로 보는 것:**
- 실시간 인식 때문에 녹음이 끊기거나 화면이 버벅이는 것. 인식이 늦으면 추정으로 넘어가야지 녹음을 해치면 안 된다.
- 업데이트 뒤 기존 원고·기록이 사라지거나, 메모가 사라지는 것.
- 어떤 화면에도 "발음 점수", "발음 채점" 같은 과장 문구를 쓰는 것. 메모 종류 이름 "발음"은 괜찮다.
- 인터넷으로 무엇이든 보내거나 받는 것 (글꼴 포함).

## 7. 방식 검토

| 방식 | 내용 | 판단 |
|---|---|---|
| **지금 구조 위에 화면을 다시 그리고 기능 추가 (선택)** | 녹음·저장·비교·억양 분석과 테스트 96개를 그대로 두고, 화면과 새 기능만 만든다. | 검증된 부분을 살리고 일이 가장 적다. |
| 화면을 처음부터 새로 짜기 | 새 구조로 전부 다시 만든다. | 이미 검증된 부분을 버리고 얻는 것이 없다. |

원고 위치를 따라가는 방식은 세 가지를 검토했다: 실시간 인식(선택, 정확하지만 무겁다), 목소리 시간으로 추정(가볍지만 어긋날 수 있다, 느린 폰에서 대체 수단으로 씀), 사용자가 직접 넘기기(단순하지만 시안의 따라오는 느낌이 없다).

## 8. 빌더에게 맡기는 것

- 색 값, 글꼴 선택(라이선스 확인), 여백, 애니메이션 세부
- 속도·크기·자주 틀림·늦음 판단의 기준값 (초기값은 위에 적었고, 상수로 둔다)
- 원고 위치 정렬 알고리즘 세부와 계산을 얼마나 자주 할지
- 릴 그림과 ON AIR 빛 효과를 그리는 방법
- 상태 관리와 폴더 구조 (지금 구조를 따른다)
