# 아나운서 발음·스피킹 교정 앱 설계 문서

작성일: 2026-11-23 · 상태: 사용자 승인 대기

## 1. 무엇을, 왜 만드나

아나운서 준비생과 현직 아나운서가 발음과 스피치를 연습할 때 쓰는 iOS·안드로이드 앱이다. 원고를 띄워 놓고 읽으면, 앱이 녹음하고 시간과 말 빠르기를 재고, 억양을 선으로 보여주고, 원고와 다르게 들린 단어를 표시해 준다.

최종 목표는 앱스토어와 구글 플레이에 출시해서 수익을 내는 것이다. 첫 출시(v1)는 모든 기능을 무료로 제공하고, 유료화는 나중에 붙인다.

## 2. 목표 (v1에 들어가는 것)

1. **녹음·다시 듣기·저장:** 연습할 때마다 녹음하고 바로 다시 들을 수 있다. 녹음은 원고, 날짜, 결과(시간, 빠르기, 억양, 비교 결과)와 함께 기록 목록에 남고, 삭제할 수 있다. 한 번 녹음은 최대 5분이다.
2. **원고 읽기·시간 재기:** 원고를 큰 글씨로 띄우고, 읽기 시작부터 끝까지 걸린 시간을 잰다.
3. **말 빠르기:** 1분에 몇 음절을 읽었는지 보여준다.
   - 음절 수는 원고 기준으로 센다. 한글은 글자 하나가 한 음절이다.
   - 숫자, 영어 약어, 기호는 읽는 소리로 바꿔서 센다. 예: "2026년"은 "이천이십육년"(6음절), "KBS"는 "케이비에스"(5음절), "%"는 "퍼센트"로 센다.
   - 문장부호와 공백은 세지 않는다.
4. **억양 선:** Metrona 보컬 기능의 음높이 선을 가져와, 읽는 동안과 다시 들을 때 목소리 높낮이를 선으로 보여준다. 목소리가 너무 단조로운 구간과, 문장 끝이 올라가는 곳(뉴스 문장은 보통 끝을 내려 읽음)을 눈으로 알 수 있게 한다.
5. **원고 비교:** 앱 안에 넣은 음성 인식 모델로 녹음을 글자로 바꾸고, 원고와 맞춰 본다. 다르게 들린 단어, 빠뜨린 단어, 덧붙인 단어를 원고 위에 색으로 표시한다. 모든 지원 기기에서 동작한다.
6. **원고:** 사용자가 원고를 붙여넣어 저장하고 연습한다. 오리지널 원고는 v1에 넣지 않는다(3장 참고).

## 3. 하지 않는 것 (v1 범위 밖)

- **내장 오리지널 원고:** 원고가 확보되면 앱 업데이트로 넣는다. v1은 원고 데이터에 분야, 난이도, 무료/유료 표시 칸만 마련해 둔다.
- **B 기능(클라우드 발음 평가):** v1 이후 단계에서 만든다(7장).
- 유료 구독과 결제
- 로그인, 계정, 서버, 클라우드 동기화
- 사용 통계·분석 도구(Firebase 등). 성과는 앱스토어와 구글 플레이 콘솔의 기본 통계(다운로드, 리텐션, 리뷰)로만 본다.
- 실제 언론사 기사 수록 (저작권 문제)
- 한국어 외 언어

## 4. 실패로 보는 것 (기능이 돌아가도 안 되는 것)

- **숨겨 둔 기능을 원격으로 켜는 구조:** 애플 심사 가이드라인(숨겨지거나 잠든 기능 금지, 현재 2.5.19)에 걸려 거절되거나 계정이 정지될 수 있다. B 코드는 출시용 빌드에 아예 들어가지 않아야 한다.
- **허락받지 않은 언론사 기사를 원고로 넣는 것**
- **할 수 없는 걸 하는 척하기:** v1의 음성 인식은 미세한 발음 차이를 잡지 못한다. 스토어 설명이나 앱 안 문구에서 "발음 채점", "발음 점수"처럼 과장하지 않는다. "다르게 들린 단어 표시"라고만 말한다.
- **녹음이 사라지는 것:** 저장한 연습 기록이 앱 업데이트나 오류로 날아가면 안 된다.

## 5. 제약

- **플랫폼:** iOS와 안드로이드를 둘 다 지원한다. 안드로이드 최소 버전은 빌더가 정하되, 13 미만 기기도 원고 비교를 포함한 모든 기능을 쓸 수 있어야 한다(사용자 결정).
- **음성 인식:** 폰 기본 인식 대신 **앱에 넣은 오픈소스 음성 인식 모델**(Whisper 계열 등)을 쓴다. 비용 0원, 서버 없음, 인터넷 없이 동작한다.
- **앱 용량:** 모델 때문에 앱이 수백 MB 커질 수 있다. 스토어의 기본 다운로드 크기 제한을 넘지 않게 모델 크기와 전달 방식(구글 Play Asset Delivery, 애플 On-Demand Resources 등)을 빌더가 정한다. 단, 우리 서버를 따로 두는 방식은 쓰지 않는다.
- **성능:** 인식은 녹음이 끝난 뒤 폰에서 돌린다. 오래된 저사양 기기에서는 느릴 수 있으므로, 진행 상황을 보여주고 기다리는 동안에도 다른 결과(시간, 빠르기, 억양)는 먼저 볼 수 있게 한다.
- **저장과 개인정보:** 녹음과 기록은 폰 안에만 저장하고, 아무것도 폰 밖으로 보내지 않는다. 스토어 개인정보 항목에는 "수집하는 데이터 없음"으로 적을 수 있어야 한다.
- **Metrona 음높이 선:** Metrona 기술 가이드(03번 파일)를 아직 받지 못했다.

## 6. 방식 검토와 결정

**앱을 만드는 기술**

| 방식 | 장점 | 단점 |
|---|---|---|
| **Flutter (선택)** | 코드 하나로 두 플랫폼을 만든다. UI를 한 번만 만든다. 성능이 좋다. | 오디오, 모델 실행 같은 기기 기능은 플랫폼별 코드나 플러그인이 필요하다. |
| React Native | 코드 하나로 만들고, Metrona가 웹 기반이면 재사용이 쉽다. | 실시간 음높이 분석처럼 무거운 작업에 손이 더 간다. |
| iOS·안드로이드 따로 | 기기 기능을 가장 잘 쓴다. | 모든 화면을 두 번 만들고 두 번 고쳐야 한다. |

**발음 교정 수준**
- A. 음성 인식으로 다르게 들린 단어만 표시 → **v1에 넣는다.**
- B. 유료 클라우드 발음 평가(Azure, 한국어 지원, 시간당 약 1.32달러) → **v1 이후에 만든다.** 사용량에 비례해 비용이 들고, 서버와 계정이 필요하고, 외국인 학습자용이라 원어민의 미세한 실수를 잡는지 검증되지 않았다.
- C. 무료는 A, 구독은 B → 유료화할 때 다시 검토한다.

**음성 인식 엔진**
- 가. 폰 기본 인식, 안드로이드 13 미만은 원고 비교 제외
- **나. 앱 안에 모델 내장 (선택)** → 모든 기기에서 되고 비용이 0원이다. 대신 용량이 커지고 일이 많아진다.
- 다. iOS에서만 원고 비교 제공

## 7. 정해진 설계 사항

- **같은 엔진을 두 플랫폼에 쓴다(설계자 판단).** 내장 모델을 iOS와 안드로이드 모두에 써서 결과가 똑같이 나오게 한다. 플랫폼별 인식 코드를 따로 관리하지 않아도 되고, 녹음 파일을 나중에 인식하는 흐름도 그대로 된다. 긴 녹음은 모델이 처리하는 단위(약 30초)로 나눠 돌리고 이어 붙인다.
- **B를 끼울 자리:** 원고 위에 결과를 칠하는 부분은 "다르게 들린 단어"와 "단어별 점수(0~100)"를 둘 다 표시할 수 있게 만든다. 결과를 만드는 쪽은 교체 가능한 부품으로 만들어, B가 들어올 때 화면을 다시 짜지 않아도 되게 한다.
- **B의 위치(설계자 판단):** B는 v1을 마친 뒤 같은 저장소 안 별도 패키지로 만든다. 출시용 빌드에는 포함되지 않도록 빌드 설정(flavor)으로 분리하고, 출시 빌드에 B 코드가 없는지 빌드 과정에서 자동으로 확인한다. Azure 키는 폰에 두지 않고, 짧게 쓰는 토큰을 발급하는 작은 서버를 거친다.
- **원고 비교 표시:** 원고 단어 단위로 맞춰 보고, 세 가지 상태(다르게 들림, 빠뜨림, 덧붙임)를 서로 다른 색으로 표시한다. 띄어쓰기나 숫자 표기처럼 받아 적는 방식 때문에 생기는 차이는 틀린 것으로 치지 않도록 정규화한다.
- **첫 화면(설계자 판단):** 내장 원고가 없으므로, 처음 켰을 때 빈 목록 대신 원고 붙여넣기 안내를 보여준다.
- **Metrona 음높이 선(설계자 판단):** 03번 파일을 받으면 그 방식을 옮긴다. 구현 시점까지 받지 못하면 자체 음높이 분석(YIN 계열)으로 만든다.

## 8. 빌더에게 맡기는 것

- 음성 인식 모델 종류와 크기, 한국어 정확도와 속도의 균형, 모델 전달 방식
- 안드로이드·iOS 최소 지원 버전
- 화면 구성과 디자인 세부 (Metrona 소통·디자인 방식 문서를 받으면 참고)
- 녹음 파일 형식과 음질, 데이터베이스 선택
- 원고 비교 알고리즘(단어 정렬) 세부
- 숫자·영어 읽기 변환 규칙의 세부 범위
- 억양 선에서 "단조로움"과 "끝 올림"을 판단하는 기준값 (초기값을 정하고 나중에 조정)
- 상태 관리, 폴더 구조, 테스트 방식
